# RELIABILITY

## 검증 기준
- 문서/하네스 변경: `npm run harness:all`.
- 일반 코드 변경: `npm run lint`, 가능하면 `npm run build`.
- UI 변경: 모바일, 태블릿, 데스크톱 수동 또는 브라우저 검증.
- 회귀 위험 영역: 로그인, 권한, 근무표, 휴가, 베스트리포트, 관리자, 팀장, 홈 뉴스 브리핑.

## 운영 주의
- middleware는 가볍게 유지한다.
- 홈 초기 로딩에서 불필요한 Supabase fan-out을 추가하지 않는다.
- Supabase query는 필요한 컬럼만 select한다.
- 재시도 루프, focus refresh, AuthGate 재조회 증가를 경계한다.

## 실패 보고
- 실패 명령을 숨기지 않는다.
- 이번 변경 원인과 기존 프로젝트 원인을 구분한다.
- 하네스 관련 실패는 수정하고 재검증한다.
- 서비스 기능 리팩터링이 필요한 실패는 확대하지 않고 보고한다.
