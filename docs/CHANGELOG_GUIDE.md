# CHANGELOG_GUIDE

## 목적
- 변경 이유와 검증 결과를 다음 Codex 작업자가 빠르게 이해하게 한다.

## 작성 원칙
- 사용자에게 보고한 변경 요약을 기준으로 남긴다.
- 서비스 기능 변경, DB 변경, 문서/하네스 변경을 구분한다.
- DB 변경은 `schema.sql` 수정과 실제 적용 SQL을 분리한다.
- 실패한 검증은 원인 분류와 함께 기록한다.

## 권장 형식
- 날짜: KST 기준.
- 범위: docs, harness, frontend, supabase, app route, CI 중 하나 이상.
- 변경: 핵심 파일과 이유.
- 검증: 실행한 명령과 결과.
- 후속: 남은 위험 또는 배포 전 확인.

## 금지
- 비밀키 값, 토큰 값, 사용자 민감 정보를 기록하지 않는다.
- 확인하지 않은 내용을 완료 사실처럼 쓰지 않는다.
